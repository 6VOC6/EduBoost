Documento de Arquitectura del Software 
1 Introducción 
 
1.1 Alcance 
El presente documento tiene como objetivo presentar la propuesta arquitectónica del software 
EduBoost, una plataforma web destinada a optimizar el aprendizaje de estudiantes que presentan 
rezago académico mediante asesorías, cursos en línea y herramientas de seguimiento académico. 
El documento describe las decisiones arquitectónicas relevantes que permiten cubrir los requerimientos 
funcionales y no funcionales del sistema, incluyendo: 
● La estructura lógica del sistema. 
● La organización de sus componentes. 
● Las tecnologías y herramientas de desarrollo utilizadas. 
● El modelo de datos y almacenamiento de información. 
EduBoost permitirá a los estudiantes acceder a asesorías personalizadas, cursos y materiales 
educativos desde una plataforma web centralizada, facilitando la interacción entre alumnos y asesores. 
 
 
2 Resumen Arquitectónico 
2.1 Tipo de Aplicación y Estilos Arquitectónicos 
El sistema EduBoost será desarrollado como una aplicación web multiusuario, accesible mediante 
navegadores web. 
La arquitectura del sistema seguirá un modelo Cliente – Servidor, donde: 
● Cliente: Navegador web del usuario. 
● Servidor: Servidor web que procesa la lógica de negocio y gestiona el acceso a la base de 
datos. 
El estilo arquitectónico principal será: 
Arquitectura en Capas 
El sistema se organizará en las siguientes capas: 
1. Capa de Presentación 
o Interfaz web para estudiantes y asesores 
o Implementada con HTML, CSS, Bootstrap y JavaScript. 
2. Capa de Lógica de Negocio 
o Procesamiento de reglas del sistema 
o Gestión de usuarios, cursos, asesorías y evaluaciones. 
 
 
3. Capa de Acceso a Datos 
o Comunicación con la base de datos SQL Server 
o Manejo de consultas y persistencia de información. 
Patrón de Diseño 
Se utilizará el patrón MVC (Model – View – Controller) mediante ASP.NET Core MVC. 
Esto permite: 
● Separar la lógica de negocio. 
● Facilitar mantenimiento. 
● Mejorar escalabilidad.

4.3 Vista de Implementación. 
El modelo de implementación de EduBoost se organiza en una arquitectura de tres capas  que 
descompone el software en los siguientes subsistemas: 
● Capa de Presentación: Interfaz de usuario web desarrollada para el acceso de estudiantes y 
asesores. 
● Capa de Negocio: Lógica del servidor implementada en ASP.NET Core que gestiona cursos, 
asesorías y evaluaciones. 
● Capa de Datos: Persistencia de información en SQL Server, comunicada mediante un mapeo 
de objetos (ORM). 
● Seguridad: Componente transversal que administra el control de acceso basado en los roles de 
la base de datos. 
 
 
4.3.1 Arquetipo de la solución 
El arquetipo de EduBoost se basa en un estilo arquitectónico de N-Capas (Multitier). La estructura se 
divide en una capa de Presentación (Navegador Web/Cliente), una capa de Negocio (Servidor Web con 
ASP.NET Core) y una capa de Datos (SQL Server). Esta separación permite que la lógica de las 
asesorías y cursos esté aislada de la interfaz de usuario, facilitando el mantenimiento y la escalabilidad 

 
 
del sistema mediante componentes desacoplados que se comunican de forma síncrona. 
4.3.2 Herramientas para la Integración 
Para la integración de los componentes de software y hardware, se utilizarán las siguientes 
herramientas: 
● Software: Visual Studio 2022 (IDE), SQL Server Management Studio (SSMS) para la gestión de 
datos y Git para el control de versiones. 
● Hardware: Servidor con arquitectura x64, mínimo 8GB de RAM para el entorno de ejecución de 
IIS y SQL Server. 
● Licencias: Licencia de Windows Server para el sistema operativo y licencias de desarrollo para 
el framework .NET. 
 
 
4.3.3 Ambiente para la Integración 
La integración se efectuará inicialmente en un servidor de desarrollo local para pruebas unitarias, para 
luego pasar a un ambiente de producción en Windows Server. La configuración técnica incluye: 
● Servidor Web: IIS (Internet Information Services) configurado para servir la aplicación ASP.NET 
Core. 
● Seguridad: Configuración de reglas de firewall para permitir tráfico únicamente por los puertos 
80 (HTTP) y 443 (HTTPS), además de la creación de una estructura de directorios que separe 
los archivos binarios (/bin) de las carpetas de contenido estático (/wwwroot) y los archivos de 
registro (/logs). 
● Línea base: Se tomará como referencia la rama main del repositorio de código, asegurando que 
todos los componentes (Base de datos, Backend y Frontend) estén sincronizados antes de la 
puesta en marcha. 
 
 
4.4 Vista de Despliegue. 
Un Diagrama de Despliegue UML  que muestra la arquitectura física de una aplicación  web de tres 
capas. Describe cómo el Cliente interactúa desde un navegador con un Servidor Web  que utiliza 
Windows Server, IIS y ASP.NET Core, el cual a su vez se conecta con un Servidor de Base de Datos 
que corre SQL Server para la gestión de los datos. 
 
 
 
 
4.4.1 Ambiente para el Despliegue 
El despliegue se realizará en un ambiente de producción bajo una arquitectura de tres capas. El 
servidor web operará sobre Windows Server utilizando Internet Information Services (IIS) como 
servidor de aplicaciones para el backend en ASP.NET Core. La base de datos se alojará en un servidor 
independiente con SQL Server, asegurando la integridad de los datos mediante una estructura de 
directorios que separe los binarios de la aplicación de los registros (logs) y archivos temporales.
